# Application Flow

## Purpose

The application flow connects the project entry point and technical sandboxes without making those sandboxes depend on menu state.

```text
Bootstrap
  -> MainMenu
      -> DeveloperMenu
          -> ProceduralWorldSandbox
```

`ProceduralWorldSandbox` remains self-contained and can still be opened and played directly in the Unity Editor.

## Responsibilities

- `ApplicationSceneCatalog` is the single runtime mapping from `SceneId` to Unity scene name.
- `SceneLoader` validates the mapping and build registration before using Unity's scene manager.
- `GameBootstrapper` coordinates startup and immediately transfers control to `MainMenu`.
- `MainMenuController` owns the UI Toolkit main/development screens and launches registered technical environments.
- `SandboxReturnToMenu` is an external navigation adapter. It does not alter procedural initialization and returns with `Escape`.

No application-flow object uses `DontDestroyOnLoad`. Single-scene transitions make scene lifetime explicit and prevent duplicate UI or services when a sandbox is reopened.

## Build Order

```text
0  Assets/Scenes/Bootstrap.unity
1  Assets/Scenes/MainMenu.unity
2  Assets/Scenes/ProceduralWorldSandbox.unity
```

The build configuration is generated by `My Game World/Build Application Flow Scenes`.

## Development Workflow

For procedural-world iteration:

```text
Open Assets/Scenes/ProceduralWorldSandbox.unity
  -> Play
```

The sandbox uses its serialized defaults, including seed and generator version. It does not require the Bootstrap scene.
